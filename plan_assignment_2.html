Overview

Build the prediction step of a Kalman filter for two dead-reckoning scenarios, and decide which is more accurate.

$$\bar{\mathbf x} = \mathbf F\mathbf x + \mathbf B\mathbf u,\qquad \bar{\mathbf P} = \mathbf F\mathbf P\mathbf F^\mathsf T + \mathbf Q$$
  1. 1D position from wheel speed (encoders / motor model).
  2. 2D position + orientation from the IMU (accelerometer + gyroscope), after an IMU position and orientation calibration.

For both: deliver F, B and Q, and answer: which dead-reckoning approach is more accurate, and why?

Deliverable: one Jupyter notebook (Toledo), code + results explained concisely. Every code block must be understood by both of us (we can be asked to explain or tweak it), so blocks are short and start with a one-line comment on what it does and what to tweak.

1.1 What is this program and how does it run?

The program is the folder A2/INTERNAL-Identification/:

FileWhat it doesChange?
INTERNAL-Identification.inoStarts the robot and creates a thread that calls update() every 10000 µs = every 10 ms. update() reads all sensors (robot.io()) then runs robot.control().No
robot.hDeclares the robot's variables: counter i, array out[12] (values sent to PC), array MV[2] (motor voltages).Only for extra variables
robot.cppRobot::control(): our code, runs every 10 ms. button0callback(): toggles control on/off with Button 0 in QRoboticsCenter.Yes

Robot::control() is a loop body repeated 100× per second. Each call does 4 things, in order (robot.cpp:17-65):

  1. Reset: out[0..11] = 0 and MV[0..1] = 0 (lines 19-21).
  2. Decide the motor voltages MV[0] (A) and MV[1] (B) (lines 24-39). ← Change A
  3. Choose what to send to the PC by filling out[0] … out[11] (lines 42-56). ← Change B
  4. Send: writeValue(k, out[k]) to the PC, setVoltageMotorA(MV[0]) / setVoltageMotorB(MV[1]) to the motors (lines 59-63).

Counter i counts calls since Button 0 was pressed. One call = 10 ms, so i = 100 means 1 second. That is how we build a voltage profile in time.

1.2 What the program does now

Current voltage block C++
if (controlEnabled()) {            // Button 0 is ON
  if (i < 200)                { MV[0] =  8.0; MV[1] =  8.0; i++; }  // first 2 s: +8 V (forward)

Problems for our assignment:

  • Always ±8 V → one voltage level only, not enough to fit a motor model (Step 4).
  • Forward 2 s / backward 2 s forever → drives back and forth, never ends by itself.
  • Only AccelX and GyroX → for 2D we need forward/sideways acceleration and the gyro around the vertical axis (probably Z, check in Step 7).

1.3 Change A · voltage profile

Replace only the block if (controlEnabled()) { ... } else { ... } in robot.cpp (lines 25-39):

Voltage staircase 3 → 6 → 9 V C++
// Voltage staircase: 3 V -> 6 V -> 9 V, each 1.5 s, then motors off (run ends by itself).
// TWEAK: levels in V[], number of levels N, duration STEP (100 = 1 s).
//        Rotate in place: put  MV[1] = -v;  instead of  MV[1] = v;
const float V[] = {3.0, 6.0, 9.0};
const int   N    = 3;                        // number of levels in V[]
const int   STEP = 150;                      // samples per level (150 x 10 ms = 1.5 s)

if (controlEnabled()) {                      // Button 0 is ON
  int s = i / STEP;                          // which level are we in? 0, 1, 2, ... (integer division)
  float v = (s < N) ? V[s] : 0.0;            // after the last level: 0 V
  MV[0] = v;                                 // motor A
  MV[1] = v;                                 // motor B (same -> drive straight)
  if (i < (N + 1) * STEP) i++;               // stop counting 1 STEP after the last level
} else {                                     // Button 0 is OFF
  MV[0] = 0.0; MV[1] = 0.0;
  i = 0;                                     // reset -> next press starts the profile again
}

i goes up by 1 every 10 ms. i / STEP (integer division) is 0 for the first 150 samples, 1 for the next 150, … so the voltage jumps 3 → 6 → 9 V. After the last level v = 0, the robot stops and i stops counting. Toggle Button 0 off/on to run the same profile again.

Role in the process

Goal 1 asks for position based on the speed. This step gives the link voltage → speed. The fitted \(a, b\) go directly into F and B of Step 5 (Option A); the residuals of this fit are reused for Q in Step 6.

Why this step

If the prediction model uses the commanded voltage as input \(u\) (Ch 5 §5.3.1.1.4: "u might be a voltage controlling how fast the wheel's motor turns"), we must know how voltage turns into speed. Physics gives the structure (first order, linear), data gives the numbers (the datasheet doesn't know gearbox friction or robot mass). Simulating on separate validation data proves the model is usable for prediction.

Tasks

  • Understand the derivation (neglect L, first-order model)
  • Fit \(a, b\) on E2 for wheel A
  • Fit \(a, b\) on E2 for wheel B
  • Check the time constant τ is physically plausible
  • Validate: simulate on E3 from voltage only, plot vs. measured
  • (Optional) add Coulomb friction / dead zone term

Model

From the appendix DC motor model: the electrical time constant \(L/R_a \approx 23\,\mu\)s is far below \(\Delta t = 10\) ms, so neglect \(L\):

$$I_a = \frac{V_a - K_e\omega}{R_a}\;\Rightarrow\; J\dot\omega = \frac{K_t}{R_a}V_a - \left(c + \frac{K_tK_e}{R_a}\right)\omega$$

First order. Discretized:

$$\omega[k+1] = a\,\omega[k] + b\,V[k]$$

Code

Fit a, b with linear regression Python
# Fit w[k+1] = a*w[k] + b*V[k] for one wheel (same tool as the notebook example).
# TWEAK: change 'wA'/'VA' for the other wheel; add np.sign(w[:-1]) as a 3rd
#        column in X to model Coulomb friction / dead zone.
from sklearn.linear_model import LinearRegression

w, V = df['wA'].to_numpy(), df['VA'].to_numpy()
X = np.column_stack((w[:-1], V[:-1]))        # regressors at time k
y = w[1:]                                    # target at time k+1
a, b = LinearRegression(fit_intercept=False).fit(X, y).coef_
tau = -dt / np.log(a)                        # time constant [s], physics check
print(f'a={a:.4f}  b={b:.4f}  tau={tau*1000:.0f} ms')
Validate on E3: simulate from voltage only Python

Role in the process

Second deliverable of goal 1: the uncertainty Q. Completes the 1D process model (F, B, Q). The propagated P is reused in Step 10 to compare predicted uncertainty with the real error.

Why this step

F and B give the mean prediction; Q tells the filter how much to trust it (every prediction adds uncertainty, Ch 2.4 / Ch 4.4). Too small Q → filter ignores measurements and drifts; too large → prediction is useless. Deriving Q from data instead of guessing is what we must justify. The P vs. real-error check shows our Q is realistic.

Tasks

  • Method 1: Q from one-step residuals
  • Method 2: \(\mathbf Q = \mathbf B\mathbf G\mathbf B^\mathsf T\) from encoder speed noise
  • Propagate P over a whole run
  • Check: real end error within \(\pm 2\sqrt{P_{11}}\)

Method 1 · from residuals (data-driven)

Literally \(E[\mathbf w\mathbf w^\mathsf T]\): the covariance of the one-step prediction error.

Q from one-step prediction error Python
# One-step prediction error on measured states -> its covariance is Q.
# TWEAK: x_meas = column_stack of encoder position and speed; u = voltage.
e = x_meas[1:] - (x_meas[:-1] @ F.T + u[:-1, None] @ B.T)
Q = np.cov(e.T)

Method 2 · from input noise (noise in control space, Ch 6.2.1.3)

For Option B the noise enters through \(\mathbf u\). With encoder speed noise \(\sigma_\omega^2\) (from steady-state parts of E2):

$$\mathbf Q = \mathbf B\,\mathbf G\,\mathbf B^\mathsf T,\qquad \mathbf G = \mathrm{diag}(\sigma_\omega^2, \sigma_\omega^2)$$

Add a term for wheel slip / radius error if the final position deviates from the tape measure.

Check

Propagate \(\bar{\mathbf P} = \mathbf F\mathbf P\mathbf F^\mathsf T + \mathbf Q\) over the whole run; the real end-position error (vs. tape) should fall roughly within \(\pm 2\sqrt{P_{11}}\).

Why this step

The assignment explicitly requires IMU position and orientation calibration. Ch 6.2.1.2 names gyroscope bias as a systematic odometry error. Accelerometers measure in their own frame at their own location: a small mounting angle leaks forward acceleration into the lateral axis; an offset from the rotation center adds centripetal acceleration during turns that is not translation. A gyro bias of 0.01 rad/s gives ≈34° heading error per minute; an accelerometer bias is integrated twice, so position error grows with \(t^2\).

Textbook model

$$\bar x = x + \delta\cos(\theta + \phi),\quad \bar y = y + \delta\sin(\theta + \phi),\quad \bar\theta = \theta + \phi,\qquad \mathbf u = \begin{bmatrix}\delta\\ \phi\end{bmatrix}$$

\(\delta\) = distance travelled, \(\phi\) = heading change in one time step. For the IMU:

  • \(\phi = \dot\theta_{gyro}\,\Delta t\) (calibrated gyro).
  • \(\delta = v\,\Delta t\), but the IMU gives no speed, only acceleration → add speed to the state.

IMU model

\(\mathbf x = [x,\ y,\ \theta,\ v]^\mathsf T\), \(\mathbf u = [a_{fwd},\ \dot\theta_{gyro}]^\mathsf T\):

$$\bar x = x + v\Delta t\cos\theta,\quad \bar y = y + v\Delta t\sin\theta,\quad \bar\theta = \theta + \dot\theta_{gyro}\Delta t,\quad \bar v = v + a_{fwd}\Delta t$$

Nonlinear in \(\theta\), so as in Ch 6.1, F and B are the Jacobians evaluated at the current estimate:

$$\mathbf F = \frac{\partial f}{\partial \mathbf x} = \begin{bmatrix} 1&0&-v\Delta t\sin\theta&\Delta t\cos\theta\\ 0&1&v\Delta t\cos\theta&\Delta t\sin\theta\\ 0&0&1&0\\ 0&0&0&1\end{bmatrix},\qquad \mathbf B = \frac{\partial f}{\partial \mathbf u} = \begin{bmatrix} 0&0\\0&0\\0&\Delta t\\ \Delta t&0\end{bmatrix}$$
Jacobians F and B with SymPy Python
# Jacobians F and B of the IMU motion model (same SymPy approach as Ch 6.2.1.3).
# TWEAK: edit fxu if you change the state or input.
import sympy as sp
x_, y_, th, v, a_f, w_g, T = sp.symbols('x y theta v a_f omega_g Delta_t')
fxu = sp.Matrix([x_ + v*T*sp.cos(th),
                 y_ + v*T*sp.sin(th),
                 th + w_g*T,
                 v  + a_f*T])
F_sym = fxu.jacobian([x_, y_, th, v])
B_sym = fxu.jacobian([a_f, w_g])
