Overview

Design a 1D linear Kalman filter that estimates the distance to the wall in front, test it offline on logged data, then run it on the robot inside a control loop that keeps the robot at a fixed distance from the wall.

$$\bar{\mathbf x} = \mathbf F\mathbf x + \mathbf B\mathbf u,\quad \bar{\mathbf P} = \mathbf F\mathbf P\mathbf F^\mathsf T + \mathbf Q \qquad \mathbf y = \mathbf z - \mathbf H\bar{\mathbf x},\quad \mathbf K = \bar{\mathbf P}\mathbf H^\mathsf T(\mathbf H\bar{\mathbf P}\mathbf H^\mathsf T + \mathbf R)^{-1}$$

The three parts of the assignment:

  1. Specify the matrices: process model F, B, its uncertainty Q, and measurement model H, R.
  2. Simulate the filter in Python on data (inputs + measurements) logged on the robot.
  3. Run the filter on the robot by filling in state_estimator.cpp.

Deliverable: the Arduino script + the relevant Jupyter notebook(s), uploaded to Toledo at least 24 h before the defense, then a defense in a timeslot you register for on Toledo. Every code block must be understood by both of us (we can be asked to explain or tweak it), so blocks are short and start with a one-line comment on what it does and what to tweak.

0.4 State units: the template uses wheel radians

robot.h:50: Meas2State = -1.0/R_WHEEL. The template converts metres to state with it (xref, _xhat at reset). So the state is not the distance in m but

$$x = -\frac{d}{r}\quad[\text{rad}],\qquad r = 0.0325\ \text{m}$$

Why this is handy: driving forward at wheel speed \(\omega\) makes \(d\) shrink by \(r\omega\Delta t\), so \(x\) grows by exactly \(\omega\Delta t\). The controller output K * (xref - _xhat) is then directly a wheel speed in rad/s for the velocity controller. Check the sign: too far from the wall ⇒ \(\hat x < x_{ref}\) ⇒ positive speed ⇒ drives towards the wall. ✓ own derivation

Decision: keep the template's units (recommended, nothing else in robot.cpp has to change). The FAQs use the state in metres (\(F=1, B=-\Delta t, H=1\)); that's the same filter in other units. If you choose metres, you must also change Meas2State and include \(1/r\) in K.

  • An IR sensor like this has a 1/raw calibration (sharp41S.cpp), so the noise grows with distance. Expect a bigger variance at 0.28 m than at 0.10 m. own derivation

4.1 From speed noise to Q

The prediction adds \(\Delta t\cdot v\), with \(v\) the mean of two noisy wheel speeds. If each wheel speed has standard deviation \(\sigma_\omega\) and the noise of the two wheels is independent:

$$\sigma_v = \frac{\sigma_\omega}{\sqrt 2},\qquad Q = (\Delta t\,\sigma_v)^2\ \ [\text{rad}^2],\qquad Q_{[\text{m}^2]} = r^2\,Q$$

This is the A2 formula \(\mathbf Q = \mathbf B\mathbf G\mathbf B^\mathsf T\) with \(\mathbf B = [\Delta t/2,\ \Delta t/2]\) and \(\mathbf G = \mathrm{diag}(\sigma_\omega^2, \sigma_\omega^2)\). own derivation

Q from σω Python
# Q from the wheel-speed noise (A2 Step 6). State units: rad^2 (template), and m^2 to compare with FAQ.
# TWEAK: sigma_w = our measured wheel-speed std from A2 (rad/s).
dt, r = 0.01, 0.0325
sigma_w = 0.35                      # rad/s, example: one encoder count per sample (A2 Step 0)
sigma_v = sigma_w / np.sqrt(2)      # mean of two independent wheels
Q = (dt * sigma_v)**2               # rad^2   -> goes into state_estimator.cpp
print(f'Q = {Q:.2e} rad^2 = {Q*r**2:.2e} m^2')

With the example σω = 0.35 rad/s: Q ≈ 6·10⁻⁶ rad² ≈ 6.5·10⁻⁹ m², inside the FAQ's typical range 10⁻⁹–10⁻⁵ m².

Units trap: Q lives in state units (rad² in the template), R in measurement units (m²). H = −r connects them. Copying the FAQ's Q in m² into the template without dividing by r² makes Q about 1000× too small.

Q from speed noise alone ignores wheel slip and an imperfect wheel radius. If the filter lags in Step 5, that's the reason to increase it. Ch 4.9 calls a filter with too small Q "smug": it stops listening to the sensor.

5.1 The filter loop

1D Kalman filter, same order and units as robot.cpp Python
# 1D Kalman filter on a logged run: correction first, then prediction (as robot.cpp).
# State x = -d/r [rad], input = mean wheel speed [rad/s], measurement = front distance [m].
# TWEAK: Q, R (Steps 3-4), P0; column names (SET 1: speeds ValueIn6/7, distance ValueIn8).
df = pd.read_csv('data/F1_run1.csv', header=1, skipinitialspace=True)
w = (df['ValueIn6'] + df['ValueIn7']) / 2          # mean wheel speed, rad/s
z = df['ValueIn8']                                 # front distance, m

dt, r = 0.01, 0.0325
F, B, H = 1.0, dt, -r
Q, R, P = 6e-6, 1.25e-5, 1e-2                      # rad^2, m^2, rad^2
x = z.iloc[0] / H                                  # start at the first measurement

xs, Ps, nus, Ss = [], [], [], []
for wk, zk in zip(w, z):
    nu = zk - H*x                                  # innovation (m)
    S = H*P*H + R                                  # innovation variance (m^2)
    K = P*H / S                                    # Kalman gain
    x = x + K*nu;  P = (1 - K*H)*P                 # corrected estimate
    xs.append(x); Ps.append(P); nus.append(nu); Ss.append(S)
    x = F*x + B*wk;  P = F*P*F + Q                 # prediction for the next sample

df['d_hat'] = H*np.array(xs)                       # back to metres for plotting
df['sd_hat'] = r*np.sqrt(Ps)                       # 1 sigma of the estimate, m
df['nu'], df['S'] = nus, Ss

6.1 The code

state_estimator.cpp, filled in C++
#include "state_estimator.h"

// PREDICTION: x = -d/R_WHEEL [rad] grows by dt * mean wheel speed.
// TWEAK: Q (rad^2) from Step 4/5.
void PredictionUpdate(const BLA::Matrix<2> &u, BLA::Matrix<1> &xhat, BLA::Matrix<1> &_Phat) {
  BLA::Matrix<1,1> F = {1.0};
  BLA::Matrix<1,1> B = {TSAMPLE};                 // 0.01 s
  BLA::Matrix<1,1> Q = {6e-6};                    // rad^2  <- Step 4/5
  BLA::Matrix<1,1> v = {(u(0) + u(1)) / 2.0};     // mean wheel speed, rad/s

  xhat = F*xhat + B*v;
  _Phat = F*_Phat*~F + Q;                          // template line 15 missed the ';'
}

// CORRECTION: front distance z [m] = -R_WHEEL * x.
// TWEAK: R (m^2) from Step 3/5.
void CorrectionUpdate(const BLA::Matrix<1> &y, BLA::Matrix<1> &xhat, BLA::Matrix<1> &nu, BLA::Matrix<1> &_Phat) {
  BLA::Matrix<1,1> R = {1.25e-5};                 // m^2  <- Step 3/5
  BLA::Matrix<1,1> H = {-R_WHEEL};                // state -> metres

  nu = y - H*xhat;                                 // innovation, m
  BLA::Matrix<1,1> S = H*_Phat*~H + R;             // innovation variance
  BLA::Matrix<1,1> K = _Phat*~H*Inverse(S);        // Kalman gain

  xhat += K*nu;
  BLA::Matrix<1,1> I = {1.0};
  _Phat = (I - K*H)*_Phat;
}

The structure is the template's; only the ?? are filled and ;/~ added. TSAMPLE and R_WHEEL come from mecotron.h (already included).
